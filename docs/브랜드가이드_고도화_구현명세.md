# 브랜드 메시지 가이드 고도화 구현 명세

작성 2026-08-11. 이 문서 하나로 구현이 끝나도록 스키마, API, 화면, 시드 데이터를 모두 담았다.

기존 구현(마이그레이션 018, `src/routes/brand_guide.js`, `public/js/views/brand_guide.js`)을 확장한다. 기존 코드를 지우지 않는다.

## 1. 목적

대외로 나가는 자료가 같은 문장과 같은 표기로 나가게 만드는 것이 목적이다. 읽는 문서가 아니라 쓰는 도구를 만든다.

담당자가 이 페이지에서 하려는 일은 셋이다.

1. 회사와 제품을 소개하는 문장을 찾아서 그대로 복사한다.
2. 쓴 원고를 붙여넣어 틀린 표기와 금지 표현을 잡는다.
3. AI에게 시킬 때 지침 원문을 통째로 복사한다.

이 셋이 각각 화면의 탭 하나가 된다.

원본 자료는 `D:\apps\브랜딩\260810 슬로건 등 대외커뮤니케이션 정리\`에 있다. 이 명세의 시드 데이터는 그 문서에서 가져왔다.

## 2. 화면 구조

### 2.1 상단 공통 영역

기존 헤더를 그대로 쓴다. 버전 배지, 현재/과거 배지, 시행일, 버전 선택 셀렉트가 이미 있다.

그 아래에 탭 3개를 추가한다.

```
[ 가이드 ]  [ 검사기 ]  [ AI 지침 ]
```

탭 상태는 `BrandGuideView.activeTab`으로 관리한다. 기본값 `guide`. 과거 버전을 열람 중이면 검사기 탭은 비활성으로 두고 "현재 버전에서만 검사할 수 있습니다"를 표시한다.

### 2.2 가이드 탭

맨 위에 고정 블록 하나, 그 아래에 접히는 섹션 목록을 둔다.

**고정 블록 — 지금 바로 쓰는 문장**

가장 많이 복사할 문장을 접지 않고 노출한다. 각 행 오른쪽에 복사 버튼을 붙인다.

| 라벨 | 값 | 복사 |
|---|---|---|
| 회사 소개 (첫 등장) | identity_full | O |
| 회사 소개 (본문 재등장) | identity_short | O |
| 회사 소개 (세 번째부터) | identity_minimal | O |
| 피지컬 AI 한 줄 풀이 | physical_ai_definition | O |

`identity_condition`은 복사 버튼 없이 아래에 작은 글씨로 붙인다.

**접히는 섹션 목록**

기본 접힘 상태이고, 클릭하면 펼쳐진다. 여러 개를 동시에 펼칠 수 있다. 펼침 상태는 localStorage `task_brand_guide_open`에 배열로 저장해 다음 방문에 복원한다.

| 순서 | 섹션 | 데이터 | 표시 형태 | 행별 복사 |
|---|---|---|---|---|
| 1 | 제품별 통점 한 줄 | brand_guide_copy (category=통점한줄) | 표 | O |
| 2 | 승인된 문구 | brand_guide_copy (그 외 category) | 표 | O |
| 3 | 쓰지 않는 표현 | brand_guide_retired_phrases | 표 | X |
| 4 | 출처 없이 쓸 수 있는 숫자 | brand_guide_facts | 표 | O (값만) |
| 5 | 용어 표기 | brand_guide_terms | 표 + 분류 필터 | X |
| 6 | 채널별 규칙 | brand_guide_channels | 카드 목록 | X |
| 7 | 내보내기 전 점검 | brand_guide_checklist | 체크박스 목록 | X |
| 8 | 아직 어긋나 있는 것 | brand_guide_issues | 표 | X |

섹션 헤더에는 제목과 건수를 함께 표시한다. 예: `용어 표기 (58)`.

5번 용어 표기는 건수가 많으므로 분류 필터 칩과 검색 입력을 섹션 안에 둔다.

8번은 버전과 무관한 데이터다. 과거 버전을 열람 중이어도 항상 현재 상태를 보여주고, 그 사실을 섹션 설명에 적는다.

### 2.3 검사기 탭

```
[ 원고 붙여넣기 textarea (rows 14) ]

[ 검사하기 ]  [ 지우기 ]        글자 수: 0 (공백 포함)

--- 결과 ---
오류 3건, 권고 2건, 확인 1건

  오류  스마트글라스 -> 스마트 글라스        2건   [본문에서 보기]
  오류  휴먼 중심 피지컬 AI 플랫폼 기업       1건   [본문에서 보기]
  권고  혁신적 -> 구체 수치로                1건
  ...

--- 원고 미리보기 (매칭 부분 강조) ---
```

동작 규칙.

- 검사는 전부 브라우저에서 수행한다. 원고를 서버로 보내지 않는다. 초안이 외부로 나가지 않아야 하기 때문이다.
- 페이지 진입 시 `GET /brand-guide/check-rules`로 규칙 목록만 받아 메모리에 둔다.
- 글자 수는 공백 포함으로 세고, 보도자료 기준 1,500자를 넘으면 숫자를 빨갛게 표시한다.
- 결과는 severity 순으로 정렬한다. 오류, 권고, 확인 순이다.
- 매칭이 0건이면 "걸린 항목이 없습니다"를 표시한다. 통과했다는 표현은 쓰지 않는다. 검사기가 잡지 못하는 항목이 있기 때문이다.
- 결과 아래에 "검사기는 표기와 금지 표현만 본다. 사실 확인과 수치 출처는 사람이 본다."를 항상 표시한다.

### 2.4 AI 지침 탭

```
[ 전체 복사 ]                        마지막 발행 2026-08-11

<pre> 지침 원문 전체 </pre>
```

- 기존 접기 방식 대신 탭 안에서 전문을 펼쳐 보여준다. 이 탭에 들어온 사람은 전문을 보러 온 것이다.
- 복사 버튼은 상단에 고정한다. 스크롤해도 따라오게 `position: sticky`를 건다.
- 관리자에게만 "항목에서 초안 생성" 버튼을 추가로 노출한다. 4.6절 참조.
- 항목 테이블이 지침 원문보다 나중에 수정됐으면 상단에 "항목이 지침 원문보다 최신입니다. 원문을 다시 발행하세요."를 표시한다. 판정은 각 항목 테이블의 `updated_at` 최댓값과 버전의 `ai_instructions_published_at`을 비교한다.

## 3. DB 마이그레이션

### 3.1 migration-019-brand-guide-items.sql

파일을 새로 만든다. 서버 시작 시 자동 실행되고 매번 재실행되므로 전부 `IF NOT EXISTS`로 쓴다.

```sql
-- migration-019: 브랜드 가이드 항목 테이블
-- 실행일: 2026-08-11
-- 변경 사유: 자유 텍스트 4개 블록으로는 검색과 검사가 불가능하여 항목별 테이블로 분리

-- 1) 기존 버전 테이블에 정체성 컬럼 추가
ALTER TABLE brand_guide_versions ADD COLUMN IF NOT EXISTS identity_full TEXT;
ALTER TABLE brand_guide_versions ADD COLUMN IF NOT EXISTS identity_short TEXT;
ALTER TABLE brand_guide_versions ADD COLUMN IF NOT EXISTS identity_minimal TEXT;
ALTER TABLE brand_guide_versions ADD COLUMN IF NOT EXISTS identity_condition TEXT;
ALTER TABLE brand_guide_versions ADD COLUMN IF NOT EXISTS physical_ai_definition TEXT;
ALTER TABLE brand_guide_versions ADD COLUMN IF NOT EXISTS ai_instructions_published_at TIMESTAMPTZ;

-- 2) 폐기 표현
CREATE TABLE IF NOT EXISTS brand_guide_retired_phrases (
  id SERIAL PRIMARY KEY,
  version_id INTEGER NOT NULL REFERENCES brand_guide_versions(id) ON DELETE CASCADE,
  phrase TEXT NOT NULL,
  retired_on DATE,
  reason TEXT,
  replacement TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_bg_retired_version ON brand_guide_retired_phrases(version_id);

-- 3) 용어 표기와 금지 표현
-- category: 제품명, 외래어, 기술용어, 기관명, 군용어, 맞춤법, 띄어쓰기, 숫자단위, 금지어
-- match_type: literal(기본) 또는 regex
-- severity: 오류, 권고, 확인
CREATE TABLE IF NOT EXISTS brand_guide_terms (
  id SERIAL PRIMARY KEY,
  version_id INTEGER NOT NULL REFERENCES brand_guide_versions(id) ON DELETE CASCADE,
  category TEXT NOT NULL,
  correct TEXT NOT NULL,
  wrong TEXT,
  match_type TEXT NOT NULL DEFAULT 'literal',
  severity TEXT NOT NULL DEFAULT '오류',
  note TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_bg_terms_version ON brand_guide_terms(version_id);
CREATE INDEX IF NOT EXISTS idx_bg_terms_category ON brand_guide_terms(category);

-- 4) 사실과 수치
-- usage_rule: 자유사용, 출처필요, 확인필요, 사용금지
-- usage는 PostgreSQL 키워드와 겹쳐 혼동을 부르므로 usage_rule로 쓴다
CREATE TABLE IF NOT EXISTS brand_guide_facts (
  id SERIAL PRIMARY KEY,
  version_id INTEGER NOT NULL REFERENCES brand_guide_versions(id) ON DELETE CASCADE,
  label TEXT NOT NULL,
  value TEXT,
  scope TEXT,
  usage_rule TEXT NOT NULL DEFAULT '자유사용',
  source TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_bg_facts_version ON brand_guide_facts(version_id);

-- 5) 승인된 문구
-- category: 통점한줄, eDM도입부, 종결변형, 영문
-- status: 확정, 초안, 미정
CREATE TABLE IF NOT EXISTS brand_guide_copy (
  id SERIAL PRIMARY KEY,
  version_id INTEGER NOT NULL REFERENCES brand_guide_versions(id) ON DELETE CASCADE,
  category TEXT NOT NULL,
  product TEXT,
  content TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT '확정',
  approver TEXT,
  note TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_bg_copy_version ON brand_guide_copy(version_id);

-- 6) 채널별 규칙
CREATE TABLE IF NOT EXISTS brand_guide_channels (
  id SERIAL PRIMARY KEY,
  version_id INTEGER NOT NULL REFERENCES brand_guide_versions(id) ON DELETE CASCADE,
  channel TEXT NOT NULL,
  tone TEXT,
  identity_placement TEXT,
  length_rule TEXT,
  hashtag_rule TEXT,
  publish_rule TEXT,
  banned_items TEXT,
  note TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_bg_channels_version ON brand_guide_channels(version_id);

-- 7) 내보내기 전 점검
CREATE TABLE IF NOT EXISTS brand_guide_checklist (
  id SERIAL PRIMARY KEY,
  version_id INTEGER NOT NULL REFERENCES brand_guide_versions(id) ON DELETE CASCADE,
  item TEXT NOT NULL,
  channels TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_bg_checklist_version ON brand_guide_checklist(version_id);

-- 8) 아직 어긋나 있는 것 (버전과 무관, 해결되면 상태만 바뀜)
-- status: 미해결, 진행중, 해결
CREATE TABLE IF NOT EXISTS brand_guide_issues (
  id SERIAL PRIMARY KEY,
  location TEXT NOT NULL,
  current_state TEXT,
  action TEXT,
  owner TEXT,
  status TEXT NOT NULL DEFAULT '미해결',
  resolved_at DATE,
  sort_order INTEGER NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## 4. API

모든 경로 앞에 `/task/api`가 붙는다. 응답 형식은 프로젝트 표준 `{ data, error, message }`를 따른다. 기존 `router.use(authMiddleware)`를 그대로 쓴다.

### 4.1 기존 엔드포인트 변경

`GET /brand-guide`와 `GET /brand-guide/:id`의 응답에 항목을 함께 담는다. 화면이 한 번의 호출로 그려지게 하기 위해서다.

```json
{
  "data": {
    "version": "1.0.0",
    "identity_full": "...",
    "identity_short": "...",
    "identity_minimal": "...",
    "identity_condition": "...",
    "physical_ai_definition": "...",
    "ai_instructions": "...",
    "items": {
      "retired": [],
      "terms": [],
      "facts": [],
      "copy": [],
      "channels": [],
      "checklist": []
    },
    "issues": []
  }
}
```

`issues`는 버전과 무관하므로 `items` 밖에 둔다.

`GET /brand-guide/history`는 그대로 둔다.

### 4.2 GET /brand-guide/check-rules

검사기 전용이다. 현재 활성 버전의 검사 대상만 가볍게 내려준다.

```json
{
  "data": [
    { "id": 12, "type": "term", "find": "스마트글라스", "match_type": "literal",
      "severity": "확인", "correct": "스마트 글라스", "note": "해시태그는 예외", "category": "기술용어" },
    { "id": 3, "type": "retired", "find": "휴먼 중심 피지컬 AI 플랫폼 기업",
      "match_type": "literal", "severity": "오류", "correct": "피지컬 AI 기업", "note": "2026-08-06 폐기" }
  ]
}
```

- `brand_guide_terms`에서 `wrong IS NOT NULL AND wrong <> ''`인 행만 담는다. `wrong`이 없는 행은 참고용이라 검사 대상이 아니다.
- `brand_guide_retired_phrases`의 모든 행을 `type: "retired"`, `severity: "오류"`로 담는다.
- 인증은 필요하지만 관리자 권한은 필요 없다.

### 4.3 항목 CRUD

관리자만 쓴다. 여덟 종류를 각각 만들지 말고 하나의 라우트로 묶는다.

```
GET    /brand-guide/items/:type            현재 버전의 항목 목록
POST   /brand-guide/items/:type            추가
PUT    /brand-guide/items/:type/:id        수정
DELETE /brand-guide/items/:type/:id        삭제
```

`:type`은 `retired`, `terms`, `facts`, `copy`, `channels`, `checklist`, `issues` 중 하나다. 라우트 안에서 화이트리스트 맵으로 테이블명과 허용 컬럼을 검증한다. 요청값으로 테이블명을 만들지 않는다.

```js
const ITEM_TABLES = {
  retired:   { table: 'brand_guide_retired_phrases', cols: ['phrase','retired_on','reason','replacement','sort_order'] },
  terms:     { table: 'brand_guide_terms',           cols: ['category','correct','wrong','match_type','severity','note','sort_order'] },
  facts:     { table: 'brand_guide_facts',           cols: ['label','value','scope','usage_rule','source','sort_order'] },
  copy:      { table: 'brand_guide_copy',            cols: ['category','product','content','status','approver','note','sort_order'] },
  channels:  { table: 'brand_guide_channels',        cols: ['channel','tone','identity_placement','length_rule','hashtag_rule','publish_rule','banned_items','note','sort_order'] },
  checklist: { table: 'brand_guide_checklist',       cols: ['item','channels','sort_order'] },
  issues:    { table: 'brand_guide_issues',          cols: ['location','current_state','action','owner','status','resolved_at','sort_order'] },
};
```

`issues`만 `version_id`를 쓰지 않는다. 나머지는 현재 활성 버전의 id를 서버에서 붙인다. 클라이언트가 보내는 `version_id`는 무시한다.

수정과 추가 시 `updated_at = NOW()`를 함께 갱신한다.

`auditMiddleware`를 모든 쓰기 요청에 적용한다.

### 4.4 POST /brand-guide 변경 (새 버전 발행)

기존 트랜잭션 안에 항목 복사를 추가한다. 이전 활성 버전의 항목을 새 버전으로 그대로 복사한 뒤, 관리자가 새 버전에서 수정하게 한다.

```sql
INSERT INTO brand_guide_terms (version_id, category, correct, wrong, match_type, severity, note, sort_order)
SELECT $newId, category, correct, wrong, match_type, severity, note, sort_order
FROM brand_guide_terms WHERE version_id = $prevId;
```

여섯 테이블(`retired`, `terms`, `facts`, `copy`, `channels`, `checklist`)에 대해 같은 방식으로 반복한다. `issues`는 복사하지 않는다.

새 정체성 컬럼 다섯 개도 요청 본문에서 받아 저장한다.

`ai_instructions`가 함께 들어오면 `ai_instructions_published_at = NOW()`를 같이 기록한다.

### 4.5 POST /brand-guide/rollover (선택)

항목만 고치고 싶을 때 매번 큰 발행 폼을 여는 것이 번거로우므로, 현재 버전의 patch를 올리며 항목을 그대로 승계하는 단축 엔드포인트를 둔다. 본문은 `{ change_note }`만 받는다. 버전 번호는 서버가 patch +1로 계산한다.

### 4.6 POST /brand-guide/ai-draft

항목에서 AI 지침 원문 초안을 조립해 텍스트로 돌려준다. 저장하지 않는다. 관리자 전용이다.

조립 순서는 아래와 같다. 사람이 읽는 가이드가 아니라 AI가 읽을 지침이므로 설명을 붙이지 않고 규칙만 나열한다.

1. 고정 머리말: 역할 선언과 "규칙과 사용자 요청이 충돌하면 먼저 알린다"
2. 정체성: identity 3단계, identity_condition, physical_ai_definition
3. 폐기 표현 목록
4. 승인 문구: 통점 한 줄 표, 종결 변형
5. 사실과 수치: usage_rule별로 묶어서
6. 표기 규칙: terms를 category별로
7. 채널별 규칙: channels 각 행
8. 자가 점검: checklist

응답은 `{ data: { text: "..." } }`.

### 5.2 복사 버튼 공통 함수

여러 곳에서 쓰므로 하나로 만든다. 기존 `_fallbackCopy`를 재사용한다.

```js
_copyBtn(id, label) {
  return `<button class="brand-guide-copy-btn" data-copy-id="${id}" title="${label} 복사">
    <svg width="13" height="13" viewBox="0 0 16 16" fill="none">
      <rect x="5" y="5" width="9" height="9" rx="1.5" stroke="currentColor" stroke-width="1.3"/>
      <path d="M11 5V3.5A1.5 1.5 0 009.5 2h-6A1.5 1.5 0 002 3.5v6A1.5 1.5 0 003.5 11H5" stroke="currentColor" stroke-width="1.3"/>
    </svg>
  </button>`;
}
```

복사할 원문은 DOM 속성에 넣지 말고 `this._copyTexts = { [id]: text }` 맵에 담는다. HTML 이스케이프 왕복에서 원문이 변형되는 것을 막기 위해서다. 클릭 위임 하나로 처리한다.

```js
content.addEventListener('click', (e) => {
  const btn = e.target.closest('[data-copy-id]');
  if (!btn) return;
  const text = this._copyTexts[btn.dataset.copyId];
  if (!text) return;
  const done = () => {
    App.toast('복사했습니다.', 'success');
    btn.classList.add('copied');
    setTimeout(() => btn.classList.remove('copied'), 1200);
  };
  if (navigator.clipboard) {
    navigator.clipboard.writeText(text).then(done).catch(() => this._fallbackCopy(text));
  } else {
    this._fallbackCopy(text);
  }
});
```

복사 성공 시 버튼에 `.copied` 클래스를 1.2초간 붙여 체크 표시로 바꾼다. 토스트만으로는 어느 버튼을 눌렀는지 알기 어렵다.

### 5.4 검사기

```js
runCheck() {
  const text = document.getElementById('bg-check-input').value;
  const hits = [];
  for (const rule of this.checkRules) {
    if (!rule.find) continue;
    let re;
    try {
      re = rule.match_type === 'regex'
        ? new RegExp(rule.find, 'g')
        : new RegExp(rule.find.replace(/[.*+?^${}()|[\]\\]/g, '\\$&'), 'g');
    } catch { continue; }   // 잘못된 정규식은 건너뛴다
    const found = [...text.matchAll(re)];
    if (found.length) hits.push({ rule, count: found.length, positions: found.map(m => m.index) });
  }
  const order = { '오류': 0, '권고': 1, '확인': 2 };
  hits.sort((a, b) => order[a.rule.severity] - order[b.rule.severity]);
  this._renderCheckResult(hits, text);
}
```

주의할 점.

- `match_type`이 `literal`이면 반드시 이스케이프한다. 시드 데이터의 `→`나 괄호가 정규식으로 해석되면 오작동한다.
- 정규식 생성 실패는 조용히 건너뛰되, 관리자에게는 콘솔 경고를 남긴다.
- 원고가 길 때를 대비해 규칙당 매칭 상한을 200건으로 둔다.
- 강조 표시는 매칭 위치를 뒤에서부터 삽입해 인덱스가 밀리지 않게 한다.
- 강조 대상 텍스트는 `escHtml`을 먼저 적용한 뒤 마크업을 넣는다. 순서를 바꾸면 XSS가 열린다.

결과 행 클릭 시 미리보기 영역의 해당 위치로 스크롤하고 해당 매칭만 다른 색으로 표시한다.

### 5.5 편집 UI

관리자에게 각 섹션 헤더 오른쪽에 `+ 추가` 버튼을, 각 행 끝에 수정과 삭제 아이콘을 노출한다. 편집은 기존 `App.openPanel`을 재사용한다. 항목 종류별로 폼 필드가 다르므로 `_itemFormHtml(type, row)` 함수 하나에 분기를 모은다.

삭제는 확인 없이 지우지 말고 `App.confirm`이 있으면 쓰고, 없으면 `window.confirm`을 쓴다.

### 5.6 빈 상태

항목이 하나도 없는 섹션은 접힌 채로 두되 건수를 `0`으로 보여준다. 펼치면 "등록된 항목이 없습니다"와 관리자에게는 추가 버튼을 표시한다.

## 6. CSS

`public/css/main.css` 끝에 추가한다. 기존 `.brand-guide-*` 클래스는 그대로 두고 새 클래스는 `.bg-*` 접두사를 쓴다.

필요한 클래스는 아래와 같다. 색은 프로젝트 주 색상 `#4F6EF7`과 기존 회색 계열을 따른다.

```
.bg-tabs, .bg-tab, .bg-tab.active
.bg-quick            상단 고정 블록
.bg-quick-row, .bg-quick-label, .bg-quick-value
.bg-section, .bg-section-head, .bg-section-arrow, .bg-section-title, .bg-section-count, .bg-section-body
.bg-table            세로선 없음, 헤더 아래 한 줄, 숫자 우측 정렬
.bg-chip, .bg-chip.active        용어 분류 필터
.bg-sev-error, .bg-sev-warn, .bg-sev-check    심각도 배지
.bg-check-input, .bg-check-actions, .bg-check-count, .bg-check-result
.bg-hit, .bg-hit.active          원고 미리보기 강조
.bg-empty
.brand-guide-copy-btn.copied
```

표는 세로 구분선을 넣지 않는다. 헤더 아래 한 줄과 행 사이 옅은 선으로 충분하다. 심각도 배지는 색만으로 구분하지 말고 글자를 함께 넣는다.

`.bg-section-head`는 버튼이므로 `cursor: pointer`와 포커스 표시를 넣는다. 화살표는 `open` 상태에서 90도 회전한다.

## 8. 구현 순서

한 번에 다 하지 않아도 된다. 아래 순서로 나눠 배포한다.

1. **마이그레이션 019, 020 + 검사기.** 용어와 폐기 표현 테이블, `GET /brand-guide/check-rules`, 검사기 탭. 이것만으로 매일 쓸 수 있다.

3. **항목 CRUD.** 관리자 편집 UI, 새 버전 발행 시 항목 복사, rollover.
4. **AI 지침 탭.** 전문 표시, sticky 복사 버튼, 초안 생성 버튼, 최신 여부 표시.

1단계와 2단계 사이에 배포해도 화면이 깨지지 않게, 항목 데이터가 없으면 기존 `message_direction`과 `comms_rules` 블록을 그대로 그리는 폴백을 남긴다.
